# Extensões

Extensões são módulos TypeScript que adicionam comportamento executável ao Pi. Use uma quando um fluxo de trabalho precisar de ferramentas, comandos, tratadores de eventos (event handlers), provedores de modelo, estado de sessão ou interface de terminal (UI) ao invés de apenas instruções.

Uma extensão roda dentro do processo do Pi com as mesmas permissões do sistema operacional. Ela pode inspecionar prompts, chamadas de ferramentas, arquivos, credenciais e histórico de sessões, portanto, carregue extensões apenas de fontes em que você confia.

Extensões típicas adicionam uma ferramenta do agent, protegem caminhos, confirmam comandos perigosos, reagem a eventos da sessão, modificam o contexto, expõem um comando ou exibem um status persistente.

## Criar e carregar uma extensão

Uma extensão exporta um factory padrão (default) que recebe o `ExtensionAPI`. A factory registra os recursos (capabilities) para o ambiente de execução da extensão atual.

Crie `~/.3pi/agent/extensions/hello.ts`:

```typescript
import type { ExtensionAPI } from "@earendil-works/3pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.registerCommand("hello", {
    description: "Show a greeting",
    handler: async (name, ctx) => {
      ctx.ui.notify(`Hello, ${name || "world"}!`, "info");
    },
  });
}
```

Inicie o Pi e execute `/hello`. Durante o desenvolvimento, carregue um arquivo diretamente:

```bash
pi --extension ./hello.ts
```

O Pi usa `jiti`, por isso extensões locais em TypeScript não necessitam de uma etapa separada de compilação. Use os [pacotes do Pi](packages.md) para extensões distribuídas e dependências.

## Adicionar ao Pi

Coloque a extensão no diretório de extensões do usuário ou do projeto. O Pi carrega arquivos TypeScript ou JavaScript diretos, bem como subdiretórios contendo um ponto de entrada (entry point) `index.ts` ou `index.js`.

Utilize um arquivo único para uma pequena extensão e um diretório para uma implementação de vários arquivos. Ponha as dependências npm num `package.json` próximo. Veja [Configuração](configuration.md) para localizações convencionais e [Configurações (Settings)](settings.md#resources) para caminhos adicionais.

O recarregamento (reload) substitui o runtime da extensão, por isso o código após `await ctx.reload()` não deve reutilizar o estado do antigo runtime. Somente extensões pessoais e explícitas de linha de comando podem participar do evento `project_trust` que ocorre antes das extensões de projeto carregarem.

## Respeitar o ciclo de vida do runtime

A factory pode ser síncrona ou assíncrona. O Pi aguarda a factory assíncrona antes que a inicialização prossiga, permitindo que ela busque configurações ou registre provedores que são necessários durante o startup.

Não inicie processos, soquetes, observadores (watchers) ou temporizadores (timers) na factory porque algumas invocações carregam extensões sem que haja o início de uma sessão.
Inicie recursos de vida longa a partir do `session_start` ou partindo do comando ou ferramenta pertinente que vier a precisar deles de modo imperativo e direto.
Desfaça e efetue o encerramento dos laços criados focados no encerramento lidando e descartando recursos atrelados em e que possuírem de escopos limitados à sessão mediante a formulação ou adoção atestada contendo um ou mais rotinas atreladas em tratamentos (handler) e voltados sob os métodos da `session_shutdown` na sua essência no estilo idempotente.

Uma execução atestada pelo percurso procede lidando perante o início passando pelo escopo sob as asas e atreladas nos tratos provenientes por parte do escopo na etapa da raiz partindo via `before_agent_start`, perpassando pelos modelos aplicados, pelas informações trafegadas contidas com as mensagens, junto aos eventos e interações em torno das atuações vindas pelas ferramentas, para culminar sob encerramento total ao esgotamento das etapas batizado nominado sob a batuta e nomeado de evento terminal: sob a sigla atestada final focada no fechamento do percurso encabeçado ou rotulado sob atesto nome de `agent_end`.
Tentativas automáticas decorrentes por refazimento via falhas (retries), por recuperações por parte de problemas nos percursos contidos nas ocorrências relatadas durante passagens nos dados gerando anomalias no sistema (recovery), pela atuação com base em sumarizações via compactações focadas visando manter em níveis salutares e razoáveis limites razoáveis do agrupamento/agregado base dos contextos passados ou pelas filas ativas formadas sob solicitações de execução base nas filas enfileirando dados englobados em esperas prontas pra execução pendente - `queued work` - todos estes, possuem sua prerrogativa tendo licença de continuarem atuando soltas nas interações procedendo a vida pós-trânsito na conclusão da listagem relatada nos eventos ocorridos acima descritos logo mais cedo num estágio precedente.

## Escolher um ponto de integração

| Recurso (Capability) | API Principal |
|---|---|
| Observar ou modificar comportamento do ciclo de vida | `pi.on()` |
| Adicionar operação chamável pelo modelo | `pi.registerTool()` |
| Adicionar um comando `/` | `pi.registerCommand()` |
| Adicionar atalho ou CLI flag | `pi.registerShortcut()` ou `pi.registerFlag()` |
| Enviar mensagem de usuário ou customizada | `pi.sendUserMessage()` ou `pi.sendMessage()` |
| Persistir dados não relacionados a contexto | `pi.appendEntry()` |
| Alterar ferramentas ativas, modelo, nível de pensamento | Métodos de controle de sessão do `pi` |
| Adicionar um provedor de modelos | `pi.registerProvider()` |
| Adicionar um servidor MCP | `pi.registerMcpServer()` |
| Rotear cada requisição ao modelo correspondente | [`pi.registerVirtualModel()`](virtual-models.md) |
| Adicionar renderização de terminal | Registro de renderizador e `ctx.ui` |
| Comunicação com outra extensão | `pi.events` |

Use as declarações exportadas em [`extensions/types.ts`](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/extensions/types.ts) para as tipagens exatas de evento, contexto, ferramenta e resultado.

### Eventos e concorrência

Os handlers rodam em ordem de carregamento/registro. `pi.on()` retorna uma função para se desinscrever (unsubscribe); as alterações não afetam um dispatch em andamento.
Alguns eventos notificam; outros transformam dados, substituem resultados, ou cancelam uma operação.
Use sempre o tipo de resultado (result type) declarado de cada evento ao invés de presumir que todos os retornos possuam efeito.

Os eventos cobrem descoberta de recursos, sessões, ciclos de vida de agent e mensagem, provedores, ferramentas e a entrada bruta (raw input).

O `before_agent_start` expõe tanto o prompt atual quanto as suas opções `systemPromptOptions` estruturadas. Dê preferência à mudança nas seções dos prompts, das ferramentas selecionadas (tools), ou das orientações de prompt; desta forma o Pi será capaz de anexar um delta à transcrição (transcript delta). Retornar o campo atrelado no parâmetro via manipulações sob a insígnia na substituição de corpo associada apontada pelo viés substituindo por si o escopo de `systemPrompt`, de mesmo modo engajando numa eventual definição via atribuição da obrigatoriedade forçante associada à fixação de modo forçoso pelo parâmetro via `forceSystemPrompt`, efetuam ambos a alteração na raiz lidando assim em toda a amplitude de forma contígua em relação substitutiva em cima perante ao escopo focado contendo todo o arranjo compondo a integralidade estrutural no que diz e tangência/atange o corpo de texto na base na confecção focada num pronto inteiro num lance só unicamente a valer na ocorrência com foco respectivo por completo na íntegra atuante visando perante escopo da execução ou "run" em si ao passo simultaneamente no decorrer engajado ao momento operante onde nas amarrações ou desdobramentos as transcrições base ou o tal associado em vias atreladas ao seu transcript continua a transcrever gerando anotações de registros nos arquivos registrando passagens nas instâncias associadas em partes isoladas sendo as devidas ou pertinentes secções sob estruturação ou em seus arranjos na estrutura dividida atreladas ali estruturadas nos agrupamentos via "structured sections". Os terceirizados na lista atreladas aos provedores receberão e são alvos das tratativas pegando os textuais resultantes contendo esses dados ali amarrados à formatações em imposição forçada engatilhados ou engajados a atuar operando e despontando servindo por ser do feitio atestando serem base liderantes à frente a atestar atrelados sendo a frente nos arranjos ou como leading system prompt.

O evento no estágio `message_end` consegue sobrepor/manipular a totalidade integral contendo atestado ou formatada da parte estrutural da mensagem formatada no viés do "finalized message" não corrompendo no que tange o seu papel do seu engajamento perante o "role" ou finalidade original/essencial em sua origem. Sob via operada pelas vias na linha `tool_call` pode por si transformar/sujar sua própria forma basilar e raiz via deformações/mutações a atuação sob as frentes nas frentes atuando e atuantes nos moldes e bases em escopos formatados originados e presentes por naturezas inerentes e base dos campos atestados como sendo vindos num input na mesma ou de vez bloquear sumariamente em e por completo o seu respectivo disparo inviabilizando ou atuando via barreira (block) contendo os processamentos no escopo de andamento sob as execuções/vias e engajamentos por debaixo nos seus desdobramentos de naturezas base focadas nas ações via (execution).
Já na listagem formatada como agrupamento dos responsáveis nos métodos atrelados na resposta ou atestando pelos trâmites focado nos campos para lidar e conter "tool_result", estes por vez atestam perante os tratos engajados no arranjo numa atuação lidando sobrepostos por agrupamento no estilo composto atuando simultâneos na engrenagem sob escopos atrelados ao modelo via "compose", operando num fluxo atestando aos que os compõem a garantia assegurando via percurso onde cada qual ali posicionado num trecho vai presenciar/ver todas as passagens geradas como fruto/produto na gestão/alterações vindas como herança por conta via alterações feitas perante aos que por ele passaram previamente ali.

<a id="provider_stream_event"></a>

`provider_stream_event` é disparado para cada evento parseado originado da transmissão no nível fornecedor (provider) logo precedentemente na exata linha de ocorrência do momento de ser submetido ao tratamento via normalizações sendo este executado pelos crivos submetidos aos testes de compatibilidade nos processos sendo o Pi responsável de tal ato antes da hora que ele assim procede (normalize it). O evento identifica qual fornecedor atua ali (provider), assim também sua versão associada da API e seu correspondente espécime via referência associando ali num (model); `event.data` engloba o dado/valoração encapsulada originada daquele contexto atestado e disponível na formatação como dado com característica da propriedade estrutural via estrutura "structured value" e exposto para e sob o Pi, de formato na primazia como versão mais bruta disponível sendo na mais antiga gerada - sendo isso não necessariamente via regra devendo transparecer e ser a literal ou primaz contendo origens nas rotas ou dados vindos pelo trajeto originando as partes dos processamentos engajados na ponta bruta formatada do pacote base contido contendo fluxos do padrão HTTP formatados via bytes do trajeto nas malhas trafegados (HTTP bytes) nem mesmo ou por tampouco os originados base e formatados/envelopados nas requisições do escopo englobados nos envelopes dos frames e pacotes englobados base nas comunicações formatadas trafegadas na via pelas partes trafegadas batizada sob e em padrão/sigla "SSE frame". Trate-o de vez tendo como conduta de abordagem no lidar e conter como leitura unicamente a ser percorrida lidando unicamente sem edição com atuação restrita atrelada a "read-only" tendo como finalidade de preservação dado ser via regra a natureza atestada nas quebras provenientes em desvios decorrentes aos escopos ou lidas que possuam na base a natureza na operação gerando deformações em virtude na confecção a partir das atuações vindas no pacote alterado com base ali por mutação de dados via "mutation" pois esse escopo detêm poderes impactantes tendo afetamentos passíveis com efeito prático podendo interferir/esbarrar/deformar (affect) todo processamento e base perante trâmites com passagens via escopo base perante fluxos no seu passo engajado pela e nas esteiras nas abordagens nos processamentos de normalizações via "normalization". O tal se enquadra de fato, em verdade detém atuação contida no formato contendo seu limite atestado batizado nas métricas restritivo atuando apenas operando sob alertas e avisos/comunicações na raiz na família atestando via notificação a rigor sendo focado por e sob notificação via sigla em restrição operada e listada sob exclusividade tipo notificação de via "notification-only" o seu dado não vai compor o bloco das memórias da vida ou dos percursos rodando listados nas trilhas do trajeto gravadas registradas não compondo sob armazenamento com característica persistente contendo nas permanências de caráter perene (not persisted).

Handlers/Tratadores ficam alinhados encadeados postos na aguarda nas engrenagens enfileirados no decorrer do trajeto englobados nos fluxos atrelados perante e sujeitos condicionados contidos enfileirados no formato associado de encadeamento operando as ordens originadas num ordenamento do tipo stream atuando nas atuações nas lidas sobre esperas nos agendamentos (awaited in stream order), ocasionando aos que possuem engajamento mais delongado agindo operando devagar (slow handlers) que venham a impactar contendo as transmissões gerando gargalos nos trâmites atestando engajamentos causando/implicando a deflagração nos casos batendo gerando delongas engajando e retardando/atrasando assim a vazão focada sobre consumições dos percursos contidos nas listas sobre consumos das linhas rodadas atestadas na banda/caminho nas comunicações operando nos percursos nos e dos ditos cujos fluxos por ali nas linhas em andamento/vazão da stream nas passagens de escoamento atrelados (delay stream consumption). Erros oriundos no nível do handler resultam listados e constam informados perante seus relatórios sem, entretanto deflagrarem impacto resultando mudanças implicando em mutações agindo englobadas nas saídas/respostas enviadas ao ou originadas desde ali originadas dos escopos retornados por parte da via provedor engajando na ou batendo na response/resposta/saída de trajeto sem afetá-las por mudança e edição. Consulte [`debug-provider.ts`](../examples/extensions/debug-provider.ts) e confira sob seu formato de amostragem na sua vertente em tipo sendo esse focado para atestações a título engajador atuando e atestado perante o viés "opt-in viewer" agrupando perante exibições agrupando fatos e listagens na raiz no escopo da base do que se chamam eventos crus (raw events) em agrupamentos sob a insígnia listados listando englobando e em prol orientando/formatando em cima listando a mensagem do dito cujos responsáveis na assistência ("assistant message").

`context` atua efetuando transformações nas instâncias nas mensagens dos turnos nos diálogos contidos atrelados via "conversation messages" excetuando aquelas nas instâncias enquadrando os atrelamentos/engajamentos perante "prompt" nas tratativas em conjunto com todas no arranjo e formato abarcadas enquadrando nas diretrizes orientando contidas pelas formatações dos avisos oriundos via ferramenta em chamadas tipo system contidas na via atuando ou vindas por ali nos escopos do arranjo e percursos sob a batuta atuando atestando o arranjo compondo as "tool system messages"; O processo via Pi executa em prol do sistema a recuperação/regeneração recompondo e recriando seu arranjo das pontas nas malhas após seus esgotamentos nas vias pós suas decorrências no termo do caminho - atuando e recuperando o status perante seu restauro (restores that state afterward). O emprego/usa das interações atestando na via engajadas no escopo focado contendo e chamando `context_with_system` restringe e limita por obrigar no trato atestando de limite contido ao viés atuando estritamente condicionado e em caráter pontual ou contido atuando unicamente voltado às restrições focadas numa dependência na submissão engajando um único/local atrelado pontualmente nos envios/recebimentos no escoamento e vazão de ponta a ponta (request-local) nas modificações em si atuando num engajamento gerando e atuando atestando e contendo obrigatoriedade em ser e conter o viés sendo o "dono/propositor/responsável mor e solitário via escopo detentor" e agindo na batuta englobando sendo contido nas malhas sob si sob responsabilidade contendo a integridade na sua gerência atuando possuindo contendo a propriedade e autoria da completude contida do transcript a rigor (must own the complete transcript), associado assim contendo na preservação de um "system message" estritamente e em ponto listado e engatado no seu ponto índice da fila/linha encabeçando na ponta zerada da estaca e começo de base: ou índice sob posição alocado num ponto zero na via.

As pontas e marcas nas etapas/eventos atuando sob as finalizações com atestamentos sob insígnias e nomes engajando chamados sob designações: atestadas via `turn_end` operando na contramão em pareamento atrelado também em viés conjugado perante `agent_before_settle` constituem e são limites das fronteiras contidas atreladas atestando terem vias focadas por si só atuantes portando aberturas atuando atestando aberturas nos engajamentos e tratativas podendo assim agir lidando em caminhos abrindo portas para trâmites (actionable boundaries). Seus manipuladores contidos em seus tratamentos no viés ou instâncias (handlers) podem efetuar encadeamentos engajando em formatação de cadeias listando "propostas" sob abordagens efetuando engates englobando e chamando nos formatos contidos propondo listando ou via `custom`, no viés englobado do evento nas tratativas com nomeação na insígnia/identificação sob as asas e batizadas no formato e viés tipo via chamados: `custom_message`, lidando ainda e sendo atuantes batizados sob e nos engates do nome focando focado em: `context_edit`, podendo enfim e atuar na listagem e na frente engajando e propondo nas tratativas focando perante propostas batizadas na alocação em chamamentos sob instâncias e vias chamadas por insígnia sendo: atestada e focada via/em engajamento em via nomeada na formatação a tratar de `compaction` sendo tratativas focadas englobando nas instâncias engajando atuando perante `entries` ou pontuamentos nas entradas. O desfecho ao seu final com o arremate operado na entrega dos encadeamentos das ditas e descritas propostas, vai assim então resultar e dar prosseguimento ao termo retornando em um engajamento listando e retornando de pronto devolvendo nas malhas atestando contendo de si mesmo `continue: true` operando gerando com engajamento por si em prol nos e de forma no atendimento via abertura focado na atuação na geração em resposta abrindo gerando e despontando gerando a ocorrência num passo na submissão seguinte em requerimento contendo focado gerando o acionamento em disparos englobando no caso em atestado sob em prol via abertura engajando na confecção perante o evento na via focada no arranjo a seguir batizado sob o próximo modelo em chamada/submissão na esteira: a `next model request`. Guarneça e cuide com vigilância garantindo restrições baseando e validando as instâncias em "condições restritas e limitadoras atestando condicionamentos contidos na gerência da conduta garantindo segurança blindada sobre o passo focado na continuação validando em cima do prolongamento operado ali a estender de base nas aprovações base contendo ali no arranjo atuante no controle ali posicionado contido sob validação atuando na contenção ali no desfecho em vias de restrição atuando e focado ali engajando contendo atuações perante o que atestamos engajando os `continuation conditions`" atestando nas razões ou amarrações geradoras por si mesmo pois engajamentos nas malhas englobando a submissão e submetendo a atuações incondicionais e com desvios em engajamentos frouxos focado num viés e descontrole incondicional sem amarras "unconditional continuation" operando lidando no percurso resultará na ocorrência gerando em engate e criação nos travamentos nas amarras com lida perante enlaçamentos nos entraves operando nas pontas sob os temidos emaranhados sem um desfecho na saída via encadeamentos gerando um fatal e incontornável loop ali e rodando nos enlaçamentos sob "loops". Aplique e atue englobando/engajando perante o viés do uso dos atestados focados lidando engajado nas tratativas contidas sob o atestado focando nos descritivos ou apontados em formatação tipo as definições de eventos no seu todo em total via base no geral, sendo os tais os ditos como declarados ali (exported event declarations) os quais servem de base atestando o molde do pacto geral de escopo listando num guia sob todos parâmetros voltados contendo a base operante orientando as garantias base focado contido atestando sob contrato listado orientando condutas perante a completude e amarrações associando em ordens operando como validações ordenadas - o `validation and ordering contract`.

<a id="cache_warming_decision"></a>

O evento em chamamento tipo `cache_warming_decision` consegue subverter em anulação perante o comportamento de praxe contido focado na atuação atrelada contida focando a atuar no contrapasso gerando sobreposição/cobertura contornando ou dominando um desfecho originado sob uma base de tempo vazio inoperante perante/na gerência focada no resguardo atestado numa inatividade ou inanição na atualidade nas esteiras do cache voltadas no "prompt-cache", atuando então no trâmite na reformulação sob a gestão da sua "refrescagem ou recarga das memórias temporárias" perante um refresh engajado por vias em submissão em comando na formatação sobrepor/engatar ou submeter passando no parâmetro atuando via: `{ action: "warm" }` contrapondo ou acionando no encadeamento em formatações engajando numa submissão do estilo passando de vez engajado em ordem perante e com a submissão a atestar batizada e focando no: `{ action: "stop" }`. ### Exposição de ferramenta

`exposure` controla de que forma o modelo acessa uma ferramenta. "Chamável" (Callable) significa ser chamável a partir de outras ferramentas através de `ctx.executeTool()` (`ctx.tools`), como os scripts da ferramenta `codemode` fazem:

- `direct` (padrão): declarada ao modelo enquanto ativa e chamável enquanto ativa.
- `model-only`: declarada ao modelo enquanto ativa, nunca chamável. Use isso para ferramentas que orquestram outras ferramentas ou solicitam o usuário.
- `codemode`: chamável sempre que registrada e listada pela ferramenta `codemode`. Não declarada ao modelo a menos que ativada explicitamente.
- `deferred`: semelhante ao `codemode`, mas ferramentas codemode não a listam; `tool_search` pode encontrá-la e ativá-la.
- `hidden`: registrada, mas inacessível. Registre novamente uma ferramenta com `exposure: "hidden"` para removê-la, uma vez que ferramentas não podem ter seu registro cancelado.

`namespace: { name, description, instructions }` agrupa ferramentas relacionadas, como os servidores MCP fazem. As ferramentas de codemode listam um namespace sob um título com sua `description`. As `instructions` contêm orientações de uso mais completas; isso não é listado, e scripts de codemode os leem com `describeNamespace(name)`.

Registrar uma ferramenta `direct` ou `model-only` a ativa; as demais exposições não são ativadas ao serem registradas. O conjunto ativo (`pi.getActiveTools()`, `pi.setActiveTools()`) é o conjunto das ferramentas declaradas para o modelo. `pi.getAllTools()` relata a `exposure`, `namespace` e `annotations` de cada ferramenta.

`annotations` são dicas sobre o que uma ferramenta faz, com o significado de anotações da ferramenta MCP: `readOnlyHint`, `destructiveHint`, `idempotentHint` e `openWorldHint`. Ferramentas MCP carregam as dicas (hints) declaradas por seus servidores. A falta delas assemelha-se ao padrão MCP: a ferramenta não tem funcionalidade exclusiva de leitura, por consequência, deve se considerar e admitir eventuais riscos associados nos tratos/engajamentos, por ter vias com comportamentos em "destructive" além também no viés aberto contendo lidas englobadas batizadas atestadas num viés engajando em saídas de via "open world". Estes campos e seus alertas "hints" nas malhas batizadas englobadas atreladas em viés de não validações, se valem ou em suma não sofrem crivos de checagem validados via "are not verified", tendo contudo suas finalidades atreladas nos tratos atestando uma ferramenta no nível contendo extensão perante o escopo da validação dos engajamentos (permission extension) ao tomar partido se baseando via decisões no apontamento engajado com e nos crivos operando lidando na base da tomada operando "can use them to decide which calls to confirm". Segue uma exemplificação batizada listando a confirmação lidando e contendo nas atestações daquelas atreladas às que são requeridas pela via contida focado em base na verificação no Codex "Codex asks approval for":

```typescript
pi.on("tool_call", async (event, ctx) => {
  const hints = pi.getAllTools().find((tool) => tool.name === event.toolName)?.annotations;
  const needsApproval =
    hints?.destructiveHint === true ||
    (!hints?.readOnlyHint && ((hints?.destructiveHint ?? true) || (hints?.openWorldHint ?? true)));
  if (needsApproval && !(await ctx.ui.confirm("Allow tool call?", event.toolName))) {
    return { block: true, reason: `${event.toolName} was not approved` };
  }
});
```

A tool that orchestrates other tools can adjust what the model sees while it is active with `prepareLoadout(loadout)`. It runs whenever the active tools change and receives the declared tools, the callable tools, and every registered tool with its exposure, namespace, and prompt guidelines. It returns replacement `descriptions` for declared tools (including its own) and `hiddenDeclarations`: active tools whose declarations requests leave out while they stay active and callable. The default system prompt leaves hidden tools out of its tool list and rules, and names no tool in the skills hint when the file reader is hidden, so the orchestrating tool should present their guidelines itself. `codemode` uses only this hook, `exposure`, and `ctx.executeTool()`, so another tool can implement the same behavior under a different name.

### Ativar ferramentas dinamicamente

Registre todas as ferramentas primeiro, mantenha as ferramentas opcionais inativas e use `pi.setActiveTools()` a partir de uma ferramenta carregadora (loader tool) para selecionar as ferramentas ativas desejadas. Os nomes já devem estar registrados; nomes desconhecidos são ignorados.

O Pi registra o prompt inicial e o conjunto de ferramentas na primeira mensagem do sistema da transcrição, em seguida, anexa mudanças na ferramenta e no prompt antes da próxima solicitação de modelo. Provedores que não consigam representar a transição receberão um ponto de verificação completo de transcrição, o que pode invalidar o prefixo em cache.

### Renderização de ferramenta

`renderCall` e `renderResult` de uma ferramenta desenham as chamadas na transcrição interativa e em exportações HTML. `pi.registerToolRenderer((toolName, next) => renderers)` escolhe os renderizadores para chamadas a qualquer ferramenta, inclusive as ainda não registradas, como ferramentas MCP numa sessão retomada antes de seu servidor ser conectado. O `next()` retorna aquilo que os demais resolutores (na ordem de carregamento das extensões) – e subsequentemente a ferramenta registrada – usariam, de maneira que `next() ?? mine` entra ali apenas de modo a suprir/preencher o que falta.

### Servidores MCP

`pi.registerMcpServer(name, config)` adiciona um servidor MCP para a sessão vigente. `config` possui o mesmo molde englobado num crivo listado das entradas de formatação via `mcpServers` no arquivo [`mcp.json`](mcp.md): `command`, `args`, `env`, e `cwd` focado em bases ligadas e pautadas ao formato na submissão de servidores stdio; `url`, `headers`, e `oauth` aplicáveis aos e de formato atestando servidores HTTP, acrescentado ademais dos campos focados na `exposure`, `toolExposure`, `description`, `enabled`, e limite atestado operando "timeout".

```typescript
pi.registerMcpServer("jira", { url: "https://mcp.example.com/jira", exposure: "codemode" });
pi.unregisterMcpServer("jira");
```

### Erros e limpeza (cleanup)

O Pi reporta erros do tratador e continua sempre que possível. A falha num tratador `tool_call` bloqueia a ferramenta a título de proteção; a falha na execução de uma ferramenta converte-se em um resultado de erro para o modelo.

Libere os recursos em `session_shutdown` mesmo quando o andamento natural da operação tentou efetuar a limpeza.
Preserve a idempotência da limpeza, pois o cancelamento, reload, reposição de sessão e a saída de processos podem, ao fim, convergir para uma mesma rota.
Use `ctx.shutdown()` ao solicitar a terminação controlada do processo.
